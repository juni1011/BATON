# BATON — 알바 첫걸음

근로계약서를 서명하기 전에 점검하고, 내 조건에 맞는 청년 지원사업과 신청 마감일까지 한곳에서 챙기는 서비스입니다.

## 해결하려는 문제

청년 알바생은 근로계약서를 받아도 최저임금, 주휴수당, 휴게시간 같은 법정 기준을 지키는지 서명 전에 확인하기 어렵습니다. 받을 수 있는 지원사업이 있어도 찾아서 신청 기간을 챙기기 쉽지 않습니다.

## 주요 기능

1. **계약서 입력** — 사진 또는 텍스트로 계약서를 넣으면 Gemini가 항목을 추출합니다.
2. **추출값 확인** — 읽은 값과 관련 원문을 보고 직접 고칩니다.
3. **점검 리포트** — 팀이 정한 규칙으로 법정 기준 충족 여부를 판정하고 사업주에게 물어볼 문장을 알려 줍니다.
4. **지원사업 추천** — 온통청년의 청년정책을 내 프로필로 걸러 주고 AI가 우선 확인할 사업을 짚어 줍니다.
5. **캘린더** — 근무일·급여일·계약 종료일과 지원사업 마감일을 한 달력에서 봅니다.

## 설계 원칙

AI는 계약서에서 값만 읽습니다. 위반 여부 판정은 근로기준법을 바탕으로 팀이 직접 만든 `ContractChecker` 규칙이 합니다.

## 기술 스택

- Java 21, Spring Boot
- MySQL 8.4
- React (지원사업 화면)
- Google Gemini API
- 온통청년 Open API

---

## 실행

Java 21과 MySQL 8.4가 필요합니다. 프로젝트 루트에서 실행합니다.

### Docker로 MySQL 준비

Docker Desktop을 실행한 뒤 환경변수 파일을 만듭니다.

```sh
cp .env.example .env
```

`.env`의 `DB_PASSWORD`를 개발용 DB 비밀번호로 변경한 뒤, **같은 터미널에서** 실행합니다.
`.env`는 Git에서 제외됩니다. Docker Compose는 이 파일을 자동으로 읽지만 Spring Boot는 읽지 않으므로 아래의 `source` 단계가 필요합니다.

```sh
set -a
source .env
set +a
docker compose up -d --wait
./gradlew bootRun
```

접속 주소: http://localhost:8080/ (index.html).
화면: /signup.html(회원가입), /upload.html(계약서 입력), /confirm.html(추출값 확인), /report.html(점검), /support.html(지원사업 추천), /calendar.html(캘린더).
계약서 점검, 일정, 지원사업 추천은 회원가입 후 로그인해야 쓸 수 있습니다(`/api/auth/**`만 비로그인으로 열려 있습니다).
현재 구현은 텍스트 파일, 붙여넣기, 가상 샘플 3종을 기본적으로 규칙으로 처리하고, "AI로 계약서를 읽어 항목을 자동으로 채우기"를 체크하면 Gemini API로 읽습니다. 계약서 사진(PNG·JPG·WEBP·GIF)은 항상 Gemini로 읽습니다(아래 "AI 분석"). PDF는 아직 읽지 못합니다. 지원사업은 `YOUTH_API_KEY`(온통청년 Open API 인증키)를 프로세스 환경변수로 주면 실제 청년정책을 보여 주고, 없으면 추천할 사업이 비어 있습니다.
서버 종료는 Ctrl+C를 사용합니다.

### AI 분석 (Gemini)

Gemini API(`generateContent`)는 두 곳에 쓰입니다. 하나는 계약서 사진·문장형 텍스트의 항목 추출이고, 다른 하나는 지원사업 추천 화면의 "AI 추천 지원사업" 패널입니다. 패널은 지원 분야 탭이나 지역을 고르면 규칙으로 걸러진 후보 중 우선 확인할 사업 최대 3개를 설명하고 신청 페이지 링크를 붙입니다. 같은 조건의 답은 서버가 30분간 저장해 다시 호출하지 않습니다.
서버 프로세스에 `GEMINI_API_KEY` 환경변수가 있어야 하며, 없으면 503을 돌려주고 화면은 내용 붙여넣기를 안내합니다. AI 사용 한도 초과(429) 등으로 실패하면 화면에는 "서버 오류가 발생했습니다"로 안내합니다.
계약서 추출은 AI가 값만 읽고, 점검 판정은 서버의 `ContractChecker` 규칙이 합니다. AI가 "있다/없다"를 판정하지 않습니다.
- 사진은 Google의 외부 AI(Gemini)로 전송됩니다. 그래서 화면에서 동의 체크를 해야 하고, 서버도 `consent=true`가 없으면 사진을 받지 않습니다.
- 사진은 디스크에 저장하지 않고 메모리에서 바로 전송하며, 사진·추출 내용은 로그에 남기지 않습니다.
- 결과는 JSON 스키마로 받고, 시급·지급일처럼 범위를 벗어난 값은 추정하지 않고 비웁니다. 분석에는 보통 10~20초가 걸리고 180초가 넘으면 504입니다.
- 설정: `GEMINI_API_KEY`(필수), `GEMINI_MODEL`(기본 `gemini-3.5-flash`), `CONTRACT_IMAGE_ENABLED=false`(사진 분석 끄기).
- 추출 대상은 `ContractInfo`의 22개 필드이며 필드 설명은 [docs/API.md](docs/API.md)에 있습니다.
- 실제 Gemini로 확인하려면 `RUN_GEMINI_IT=1 CONTRACT_IMAGE_GEMINI_API_KEY=... ./gradlew test --tests '*ContractImageGeminiIT'`를 실행합니다.

MySQL의 데이터베이스·사용자 이름은 `easyton`, 포트는 `3306`입니다. 다른 포트나 주소를 쓰면 `DB_URL`로 바꿉니다. `app_users`(회원)와 `user_data`(계정별 저장 데이터) 테이블은 서버 시작 시 `schema.sql`로 생성하며, 기존 테이블과 회원 데이터는 유지합니다. 스키마가 변경되면 별도 마이그레이션이 필요합니다.
`docker compose down`은 DB 컨테이너를 종료하지만 볼륨의 회원 데이터는 보존합니다. DB 비밀번호는 볼륨 최초 생성 시 적용되므로, 이미 생성한 DB의 비밀번호를 변경하려면 MySQL에서도 변경해야 합니다.

### 이미 설치된 MySQL 사용

기존 MySQL을 사용한다면 Docker 실행을 생략하고, 관리자 계정으로 데이터베이스와 앱 계정을 준비합니다. 비밀번호 예시는 실제 값으로 바꿉니다.

```sql
CREATE DATABASE IF NOT EXISTS easyton CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_as_cs;
CREATE USER 'easyton'@'localhost' IDENTIFIED BY 'your-db-password';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, REFERENCES ON easyton.* TO 'easyton'@'localhost';
```

앱 계정이 이미 있다면 `CREATE USER`를 생략합니다. 실행할 터미널 또는 IDE 실행 설정에 아래 환경변수를 설정합니다.

```sh
export DB_URL='jdbc:mysql://localhost:3306/easyton?connectionTimeZone=UTC&characterEncoding=UTF-8'
export DB_USERNAME='easyton'
export DB_PASSWORD='your-db-password'
./gradlew bootRun
```

### 회원가입 동작

`/signup.html`에서 이름, 이메일, 비밀번호, 비밀번호 확인을 입력하면 `POST /api/auth/signup`으로 저장합니다.
이메일 앞뒤 공백과 대소문자를 정규화하고, 같은 이메일은 DB의 UNIQUE 제약으로 중복 가입을 막습니다.
서버에서도 이름(1~40자), 이메일(최대 254자), 비밀번호(8~128자), 비밀번호 일치를 검사합니다.
비밀번호는 Spring Security의 PBKDF2 해시와 무작위 salt로 저장하며 API 응답에 원문이나 해시를 포함하지 않습니다.
가입 성공 시 로그인 화면으로 이동하고 로그인 버튼 아래에 환영 메시지가 표시됩니다.
로그인은 `POST /api/auth/signin`, 세션 확인은 `GET /api/auth/me`, 로그아웃은 `POST /api/auth/signout`을 사용합니다. 홈의 추천 받기·전체 보기 링크는 로그인 상태를 확인하며, 로그인 후 원래 선택한 화면으로 이동합니다. 이메일 인증은 아직 구현하지 않았습니다.
로그인하면 계약 정보, 점검 결과, 일정, 프로필, 추천 결과를 계정(`user_data`)에 저장해 다른 브라우저에서도 이어서 쓸 수 있습니다. 서버 저장에 실패한 값은 이 브라우저(`localStorage`)에 남겨 두고 다시 보냅니다. 자세한 규칙은 [docs/API.md](docs/API.md)의 "계정별 데이터 저장"을 참고합니다.

## 지원사업 추천 화면 (React)

`/support.html`의 입력·지도·추천 결과는 React로 구성합니다. 기존 Spring Boot 서버에서 그대로 제공하며, 실행에 외부 CDN은 필요하지 않습니다.
입력 화면은 나이·거주 지역·현재 상태·거주 형태·가구 소득의 5개 항목입니다. 거주 지역은 시·도와 시·군·구 선택창을 같은 카드에 두며, 시·도를 고르면 같은 지도가 확대되어 시·군·구를 선택할 수 있습니다. API에 전달하는 프로필의 6개 필드는 유지합니다.
수정할 소스는 `frontend/support/`, 화면 스타일은 `src/main/resources/static/css/support.css`와 `support-map.css`입니다.

```sh
npm ci
npm run build
./gradlew processResources
```

`npm run dev`는 React 소스 변경을 감지해 기존 정적 번들을 다시 만듭니다. Spring Boot 서버와 함께 사용하며 별도 프론트 서버를 만들지 않습니다. 변경 후 `./gradlew processResources`와 브라우저 새로고침으로 확인합니다.
빌드한 `src/main/resources/static/js/support.js`와 라이선스 파일은 저장소에 포함하므로 Java 서버만 실행해도 화면을 볼 수 있습니다. 생성 파일 대신 `frontend/support/`의 JSX를 수정해 주세요.
연령 그림은 화면 표시를 위해 0~18세·19~34세·35~64세·65세 이상으로 구분하며 추천 판정은 기존 서버 규칙을 사용합니다.
지도 데이터 출처와 라이선스는 `frontend/support/MAP_DATA_LICENSE.md`를 참고합니다.
결과 위의 지원 분야 탭은 `category`를 별도 요청 필드로 전송하고 프로필과 함께 저장하며, 누르면 같은 프로필로 다시 검색하고 AI 추천도 갱신합니다. 결과는 온통청년의 실제 청년정책이며 검색 결과가 없으면 0건 안내를 표시합니다. 결과 카드의 "마감일을 캘린더에 추가"를 누르면 일정을 저장하고 캘린더 화면으로 이동합니다.
지도와 선택창은 양방향으로 연동합니다. 항목 선택을 마치면 다음 빈 항목으로 이동하며, 나이·직접 입력은 입력을 멈춘 뒤 1.1초 또는 Enter로 확정합니다. 직접 스크롤하거나 다른 입력에 포커스를 옮기면 대기 중인 자동 이동은 취소됩니다. 전체 입력을 마쳐도 추천 요청은 사용자가 버튼으로 실행합니다.

## 테스트

```sh
./gradlew test
```

테스트는 기본적으로 H2 메모리 DB를 사용하므로 MySQL이나 `DB_PASSWORD` 없이 실행할 수 있습니다. 로그인 필수 설정은 테스트에서 끄고(`app.auth.required=false`), 로그인 필수 동작은 `LoginRequiredTests`가 따로 검증합니다.
컨텍스트 로딩, 계약서 추출·점검 규칙, 지원사업 매칭, 회원가입 저장·해시 검증·이메일 중복·잘못된 입력·비밀번호 길이 경계를 확인합니다.
결과 보고서는 `build/reports/tests/test/index.html`에서 확인합니다.

별도 MySQL에서 같은 테스트를 실행하려면 `TEST_DB_URL`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD`를 설정하고 `./gradlew test --rerun-tasks`를 실행합니다.
**회원가입 테스트는 매 테스트 전에 `app_users`를 비우므로 반드시 테스트 전용 DB를 사용합니다.**

## 주요 기능 상세

청년 알바생은 서명 전에 근로계약서를 점검하고, 자신의 조건에 맞는 지원사업과 신청 마감일을 확인할 수 있습니다. API 요청·응답 예시는 [docs/API.md](docs/API.md)에 있습니다.

### 사용자 흐름

1. **계약서 입력** — 사진 업로드(Gemini 분석), 텍스트 붙여넣기, 가상 샘플 3종 중 하나를 선택할 수 있습니다. AI는 시급, 근로시간(요일별 시간 포함), 계약 기간, 지급일, 주휴일 요일, 연차유급휴가, 임금 지급방법, 계약서 교부 조항과 관련 조항을 추출합니다.
2. **추출값 확인** — 읽은 22개 항목과 관련 원문을 보여주고 사용자가 수정할 수 있게 합니다. 연차·교부 조항은 "적혀 있음 / 없다고 적힘 / 확인 안 됨" 중에서 고릅니다. 확인된 값으로 점검과 계약 일정 생성을 실행합니다. 원문에서 확인할 수 없는 값은 `null`로 전달합니다.
3. **점검 리포트** — 필수 기재사항, 최저임금, 주휴수당, 휴게시간, 임금 지급일, 주휴일 요일, 연차유급휴가, 임금 지급방법, 계약 종료일, 계약서 교부와 위약금 조항을 살피고, 부족한 부분을 법 조항별로 모아 보여주며, 계산에 필요한 정보가 있으면 예상 세전 월급을 보여줍니다. 조항의 쉬운 설명과 사업주에게 물어볼 문장, 공식 상담 창구를 제공합니다.
4. **지원사업 추천** — 나이, 거주 지역, 현재 상태, 거주 형태, 가구 소득을 바탕으로 신청 가능·확인 필요·신청 불가를 판정합니다. 온통청년의 실제 청년정책을 최대 50건까지 보여주며, 사업별 판정 이유, 신청 기간, 필요 서류, 공식 신청 링크를 표시합니다. AI 추천 패널이 우선 확인할 사업을 짚어 줍니다.
5. **캘린더** — 확인된 계약 정보로 근무일·급여일·계약 종료일을 생성합니다. 사용자는 추천 사업의 마감일과 개인 일정을 직접 추가할 수 있습니다. 월간 달력과 다가오는 일정에 표시하고, 계약 일정을 다시 생성해도 이미 추가한 개인 일정과 지원사업 마감일은 유지합니다.

### 동작 기준

- 기존 Spring Boot 프로젝트에서 HTML·CSS·JavaScript 화면과 API를 함께 제공합니다. 회원가입·로그인 후 모바일에서도 이용할 수 있고, 진행 상태를 계약서 입력·확인 → 점검 → 추천 → 일정의 4단계로 표시합니다.
- 임금·근로시간 계산과 지원 자격 판정은 서버 규칙으로 처리합니다. AI는 문서 추출과 지원사업 추천 설명에만 사용하고, 리포트에는 규칙으로 계산한 결과와 관련 원문, 법 조항을 표시합니다. 근거가 부족하면 `확인 필요`로 안내합니다.
- 최저임금 기준은 `ContractChecker`의 `MINIMUM_WAGE`에 출처(최저임금위원회 의결·고용노동부 고시, 2025~2027년)와 확인일(2026-11-14)을 주석으로 적어 두었습니다. 지원사업 조건은 온통청년 Open API가 주는 정책 정보를 그대로 사용합니다. 업로드 원본은 저장하지 않고 요청 처리 후 폐기합니다. 화면에서 주민등록번호·전화번호·계좌번호를 가려서 올리도록 안내하고, AI에는 개인 식별 정보를 결과에 넣지 않도록 지시합니다. AI 키는 서버 환경 변수로 관리합니다.
- `YOUTH_API_KEY`가 없으면 추천할 지원사업이 비어 있으며 가상 사업은 만들지 않습니다. 가상인 것은 계약서 샘플 3종뿐이며 실제 업체·인물과 관계없습니다. 일정은 로그인한 계정에 저장하고, 서버 저장에 실패하면 브라우저의 `localStorage`에 남겨 다시 보냅니다.
